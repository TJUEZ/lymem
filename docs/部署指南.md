# 麟忆尽智 lymem · 银河麒麟 V11 部署与验收指南

本文面向比赛评审、部署人员与 OS Agent 集成人员，目标是在银河麒麟桌面操作系统 V11
真机上完成可复现安装，并证明系统实际使用了麒麟端侧 Embedding 能力。

> 正式验收必须使用 `kylin(auto)`、`kylin-dbus` 或 `kylin-kytensor` 通道。
> `LYMEM_EMBEDDER=hash` 仅用于开发和故障诊断，不能作为麒麟 SDK 适配验收结果。

## 1. 环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | 银河麒麟桌面操作系统 V11，使用桌面登录用户执行 |
| 架构 | 当前发布包为 x86_64/amd64；ARM64 需在对应真机重新构建和测试 |
| 端侧 AI | `kylin-ai-runtime` 与系统 Embedding 服务已安装并随桌面会话启动 |
| 端口 | 本机 TCP 8801 可用；服务只监听 `127.0.0.1` |
| 可选能力 | LLM API；不配置时使用规则通道，不影响本地记忆、检索和遗忘 |

不要使用 `sudo lymem start` 启动服务。麒麟 AI runtime 的 DBus 套接字属于当前桌面用户，
root 进程通常无法访问正确的用户会话通道。

## 2. 安装前检查

```bash
cat /etc/os-release
uname -m
id -u
test -S "/tmp/.kylin-ai-runtime-unix/$(id -u)/core-textembedding.sock" \
  && echo "Embedding DBus socket: OK" \
  || echo "Embedding DBus socket: MISSING"
curl -fsS http://127.0.0.1:8000/v2/health/ready \
  && echo "kytensor: OK" \
  || echo "kytensor: unavailable (DBus 正常时可忽略)"
```

DBus 与 kytensor 均不可用时，先确认已经登录图形桌面并检查麒麟 AI runtime 服务。不要直接
切换到 `hash` 后完成正式验收。

## 3. 安装

### 3.1 免 root 用户安装（推荐）

```bash
tar -xzf lymem-0.1.0-linux-amd64.tar.gz
cd lymem-0.1.0-linux-amd64
./install-user.sh
~/.local/bin/lymem status
```

程序、配置、数据和日志依次位于 `~/.local/lib/lymem/`、`~/.config/lymem/env`、
`~/.local/share/lymem/` 和 `~/.local/state/lymem/server.log`。

### 3.2 deb 安装

```bash
sudo apt install ./lymem_0.1.0_amd64.deb
/opt/lymem/lymem-ctl start
/opt/lymem/lymem-ctl status
```

`sudo` 只用于安装包；启动命令仍由桌面登录用户执行。安装后也可从应用菜单打开“麟忆尽智”。

### 3.3 源码构建

```bash
cargo build --release --locked
LYMEM_PORT=8801 ./target/release/lymem-server
```

发布构建使用 `./packaging/build-dist.sh`。

## 4. 配置

编辑 `~/.config/lymem/env`。竞赛真机推荐保持自动通道：

```bash
export LYMEM_PORT=8801
export LYMEM_DATA_DIR="$HOME/.local/share/lymem"
export LYMEM_VECTOR_BACKEND=kylin
# 默认即为 auto，正式验收不要设置为 hash
# export LYMEM_EMBEDDER=auto
```

可选 LLM 配置：

```bash
export LYMEM_LLM_API_KEY="..."
export LYMEM_LLM_BASE_URL="https://your-provider.example/v1"
export LYMEM_LLM_MODEL="your-model"
```

配置变更后执行 `lymem restart`。

## 5. 启动与验收

```bash
lymem start
lymem status
curl -fsS http://127.0.0.1:8801/api/v1/health
curl -fsS http://127.0.0.1:8801/api/v1/status
```

浏览器打开 `http://127.0.0.1:8801/viewer`，按以下顺序验收并截图或录屏留证：

1. **端侧通道**：状态 API 显示 `embedder=kylin(auto)`、维度 768，且
   `vector_backend=kylin-vector-engine`；不得显示 `hash` 或 `sqlite-vec`。
2. **多源接入**：总览灌入演示数据；记忆库检查工具结果、行为、配置和会话条目。
3. **偏好捕捉**：执行规则挖掘和会话提取，检查版本时间线与场景字段。
4. **知识冲突**：同一知识修改时间或数值后重提，检查冲突台账并手动改判。
5. **检索性能**：连续检索并记录返回引用与耗时，确认单次小于 500 ms。
6. **安全遗忘**：先检索、预览遗忘范围、执行软删除、再次检索确认不可召回。
7. **记忆流转**：灌入情景记忆后执行“蒸馏一轮”，检查各层计数变化。
8. **量化评测**：运行内置评测；正式报告以离线 benchmark 原始结果为准，不以页面静态值代替。

保存 `/etc/os-release`、`uname -a`、状态 API JSON、服务日志、评测命令、评测原始结果和管理台
录屏。报告中的每个指标都应能追溯到原始文件和 Git commit。

## 6. OS Agent 接入

- REST：`/api/v1/memories`、`/api/v1/search`、`/api/v1/preferences` 等；
- MCP Streamable HTTP：`http://127.0.0.1:8801/mcp`；
- OpenAI 兼容 Embedding 代理：`http://127.0.0.1:8801/v1/embeddings`。

接入示例见 `integrations/deepseek-harness/README.md` 与 `integrations/opencode/opencode.json`。
集成验收至少展示一次“Agent 写入工具结果 -> 形成长期记忆 -> 新会话检索 -> 影响工具选择”的
完整闭环，而不是只在管理台手工导入。

## 7. 备份、升级与卸载

停止服务后备份，避免复制 WAL 中间状态：

```bash
lymem stop
tar -C "$HOME/.local/share" -czf "lymem-backup-$(date +%Y%m%d-%H%M%S).tar.gz" lymem
lymem start
```

升级前先备份，再安装新包并运行 `lymem restart`。恢复时停止服务，用备份目录替换
`~/.local/share/lymem` 后重新启动。用户安装包使用 `./uninstall-user.sh`；deb 使用
`sudo apt remove lymem`。默认保留用户数据。

## 8. 故障排查

```bash
lymem logs
ss -ltnp | grep 8801
curl -v http://127.0.0.1:8801/api/v1/health
```

| 现象 | 检查与处理 |
|---|---|
| 启动失败 | 查看服务日志，确认端口未占用 |
| 显示 hash/64 维 | 检查 `LYMEM_EMBEDDER`，再检查 DBus socket 与 kytensor |
| root 下无麒麟嵌入 | 停止 root 进程，改用当前桌面用户启动 |
| DBus 偶发失败 | 检查自动重试和 kytensor 降级日志，确认 8000 端口状态 |
| 管理台打不开 | 先用 health API 区分服务问题和浏览器问题 |
| 数据迁移后异常 | 确认整个数据目录一并迁移且目标用户有读写权限 |
