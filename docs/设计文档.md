## 1 问题定义与总体方案

### 1.1 赛题痛点归纳

赛题背景指出的核心矛盾是**记忆来源的多源性**与**记忆治理能力的缺位**之间的落差。我们将其拆解为四个具体设计问题：

| # | 痛点（赛题原文提炼） | 设计必须回答的问题 |
|---|---|---|
| P1 | 工具调用结果结构化不足、数据质量参差不齐 | 异源异构数据如何统一建模、清洗与校验？ |
| P2 | 偏好提取不精准、版本管理混乱、跨场景不一致 | 偏好如何自动且可信地产生、演进、回溯？ |
| P3 | 新旧知识冲突滞后、关联检索精度有限 | 知识如何结构化沉淀、碰撞时如何仲裁、如何被精准找回？ |
| P4 | 端侧资源受限，检索延迟需 ≤500ms | 在国产桌面 OS 上如何做到轻量、低延迟、离线可用？ |

在此基础上叠加安全合规（敏感信息、遗忘权）与系统兼容（短/中期记忆流转）两条硬约束，以及"用标准化数据集证明效果"的验证要求。

### 1.2 设计原则

1. **端侧优先**：全部能力在本机闭环（嵌入、检索、仲裁、遗忘），LLM 仅作可选增强，断网降级不失效；
2. **规则先行、LLM 增强**：每个智能环节（冲突仲裁、遗忘解析、偏好提取、蒸馏）都有确定性规则基线，LLM 可用时自动升级，保证行为可预期、可测试；
3. **一切可追溯**：写入、仲裁、遗忘、分发全走 `audit_log`；偏好与知识均为追加式版本链，任意时点可回放；
4. **可插拔**：核心库（`lymem-core`）只依赖 `Embedder`/`LlmJudge` 两个 trait，麒麟嵌入与 MiniMax 网关是 trait 的具体实现，可替换、可 mock——这也是全部评测可复现的前提。

### 1.3 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│  接入层   REST /api/v1/*（axum）│ /v1/embeddings 代理 │ MCP（DSH 集成）│
│           Web 管理台 viewer（7 页，内嵌单文件前端）              │
├─────────────────────────────────────────────────────────────┤
│  服务层   lymem-server：41 条路由（灌入/检索/问答/偏好/知识/冲突/ │
│           遗忘/敏感/评测/中枢/嵌入代理），阻塞 LLM 调用 spawn_blocking│
├─────────────────────────────────────────────────────────────┤
│  核心库   lymem-core（冻结 v0.1.0 指标基线）                    │
│           ingest · preference · conflict · retrieval ·       │
│           promotion · forget · sensitive · hub · store       │
├─────────────────────────────────────────────────────────────┤
│  适配层   lymem-kylin（麒麟嵌入：DBus→kytensor 双路）           │
│           lymem-llm（MiniMax 网关，Anthropic 协议，规则兜底）    │
├─────────────────────────────────────────────────────────────┤
│  存储     SQLite（元数据/版本链/图边/审计）+ sqlite-vec（向量 ANN）│
│           + tantivy（BM25 全文），单文件库+全文目录，拷贝即备份   │
└─────────────────────────────────────────────────────────────┘
```

### 1.4 四层记忆体系（核心数据模型）

一条记忆 = `MemoryRecord{tier, kind, title, content, scene, entities[], sensitivity, confidence, access_count, version…}`。四层与赛题条款的对应：

| 层 | 介质 | 存什么 | 对应条款 |
|---|---|---|---|
| 工作记忆（短期） | 进程内存环形缓冲 | 当前会话上下文 | (6) 短期记忆 |
| 情景记忆（中期） | SQLite | 会话轮次、工具调用轨迹原文 | (6) 中期记忆 |
| 知识记忆（长期） | SQLite+版本链 | 工作流程/历史案例/模板，结构化实体 | (3) |
| 偏好记忆（长期） | SQLite+版本链 | 操作习惯/输出风格/安全策略 | (2) |

统一按"库标签"（scene）分库，支持整库检索与整库遗忘——这是多源数据"贴标入库、分区治理"的基础。

## 2 需求逐条设计

### 2.1 条款(1) 多源数据整合模块

> 构建多源数据整合模块，支持工具执行结果、用户行为数据、手动配置信息等数据的统一接入，建立数据清洗、格式标准化与质量校验机制。

**设计**：定义统一事件协议 `Event{type, data}`，四类源全部归一为 `tool_result | user_behavior | manual_config | conversation`，走同一条五步接入管道：

```
统一事件 → ①清洗（空白规范化/长度上限）→ ②敏感识别分级（见 2.5）
        → ③实体抽取（规则）→ ④去重指纹校验 → ⑤入库（向量+全文+图边三索引）
        → 偏好快通道联动（见 2.2）
```

- **质量校验双模式**：`/api/v1/ingest/report` 只出报告不入库，逐事件给出 归类/清洗前后字数/敏感级/实体/重复判定；确认后 `/api/v1/memories` 正式入库——"先质检、后入库"而非入库后补救；
- **文本长文档**：粘贴/上传通道按 800 字块或章节标记（如「第 N 回」）自动切分，逐块贴源标签；
- **幂等**：去重指纹使重复灌入安全跳过（报告明示"重复跳过"）。

**实现落点**：`lymem-core/src/ingest.rs`；API `/api/v1/ingest/report`、`/api/v1/memories`、`/api/v1/ingest/chapters`；界面「记忆库」页（粘贴/上传/事件 JSON 三 tab，质量报告表格）。

**实测证据**：事件 JSON 质量报告逐行输出清洗与校验判定；62 万字《三国演义》整书 120 回按章切分灌入成功（144 条记忆/126 个章节块）。

### 2.2 条款(2) 偏好记忆动态捕捉

> 构建偏好记忆动态捕捉模块，基于多源融合数据，实现用户操作习惯、输出风格、安全策略等偏好的自动提取与版本化管理，实现跨场景偏好适配与回溯。

**设计**：双通道提取 + 追加式版本链 + 场景作用域，三者合成"可回溯的偏好时间线"。

- **快通道（规则，纯 Rust，离线可用）**：`preference_rules_from_tools(lookback, min_count, share)` 滑窗统计工具调用结果——同一任务下某工具使用频次超过阈值（默认 ≥3 次且占比过半）即沉淀为偏好（如 `tool_choice.doc_edit = libreoffice`），附置信度=使用占比、evidence=支撑记忆 id，**可溯源到原始记忆**；
- **慢通道（LLM，可选）**：`preference_llm_extract` 从会话陈述（"我爱喝奶茶""输出用中文"）提取结构化偏好增量，覆盖规则无法捕捉的软性偏好；
- **版本化**：`preferences(key, current_version)` + `pref_versions(version, value, evidence, source, confidence, scenes, valid_from, valid_to, superseded_by)`。每次写入=追加新版本并关闭旧版本（`valid_to` 置位），同值重复写入忠实记录并标注——不做覆盖，历史永不丢失；
- **跨场景适配与回溯**：`effective_preferences(scene)` 按 `scenes ∈ {"*", 具体场景}` 求生效集，检索重排（见 2.3）按场景消费偏好；`preference_at(key, at)` 任意时间点回放，`/preferences/{key}/history` 出完整时间线。

**实现落点**：`lymem-core/src/preference.rs`；API `/api/v1/preferences*`（list/set/get/history/mine/extract）；界面「偏好中心」页（双通道按钮、偏好库、版本时间线、手动写入）。

**实测证据**：PrefEval 偏好遵循 **98.0%**（mem0 73.0%）；「我爱喝奶茶」会话陈述 → `session.diet.milk_tea`（带 memory_id 溯源）；偏好类目覆盖工具选择/输出风格/安全策略/饮食生活习惯等（演示库实测 8 键并存、版本链完整）。

### 2.3 条款(3) 知识记忆结构化整合机制

> 设计知识记忆结构化整合机制，实现新旧知识冲突处理、关联检索优化，支持工作流程知识、历史案例、可复用模板的结构化存储与智能调用。

**设计**：知识写入即走"冲突四步管道"，检索用"三路混合 + 偏好重排"。

**冲突四步管道**（写入同步执行，冲突不滞后）：

```
写入知识 → ①检测：实体门（新旧记录实体交集）+ 内容块最大余弦相似度 ≥0.8
        → ②分类：numeric 数值更新 / method 方法过时 / premise 前提失效 /
                  spurious 表面相似 / value_conflict 取值矛盾
        → ③仲裁：规则优先（数值变化→新版取代或共存、信任度比对），
                  规则不确定时 LLM 仲裁，决策者 decided_by 落账
        → ④版本化：supersede 取代 / coexist 共存 / merge 合并 / keep_old，
                  全部落入 conflicts 台账（含理由与相似度）
```

**三路混合检索 + 偏好重排**：

```
查询 → 嵌入 → ①向量 KNN（sqlite-vec，语义）②BM25（tantivy，精确词面）
             ③实体图扩展（共现图邻居，多跳关联）
    → 层级/敏感过滤 → RRF 融合（k=60，三路加权 w_vec/w_bm25/w_graph）
    → 偏好重排（生效偏好提权，如"文档编辑用 libreoffice"）
    → 命中返回（含 snippet 与三路得分）+ 访问计数（供蒸馏与巡检）
```

- **结构化存储**：知识条目带 title/实体列表/库标签/版本链，工作流程、案例、模板同构入库，实体图随写入增量建边；
- **智能调用**：`/api/v1/ask` 在检索命中上做生成式直答并附 [n] 引用；纯检索路径不含任何 LLM 调用（延迟指标即此路径）。

**实现落点**：`lymem-core/src/conflict.rs`、`retrieval.rs`；API `/api/v1/knowledge`、`/conflicts`、`/search`、`/ask`；界面「知识与冲突」页（一键"演示冲突：改值重提"、仲裁台账）与「记忆库」检索问答卡。

**实测证据**：受控冲突用例 30 组正确率 **93.3%**（目标 ≥88%）；实测样例：同实体改值重提（16:00→18:00）触发 `numeric_update → coexist`，台账记录"相似度 0.968，数值变化=true"；七站检索召回 85.7%–100%（见 §4）。

### 2.4 条款(4) 端侧部署与检索延迟 ≤500ms

> 适配端侧部署需求，调用银河麒麟国产桌面操作系统 embedding SDK，设计轻量化存储方案，确保检索响应延迟 ≤500ms。

**设计**：国产嵌入 SDK 直连 + 单文件嵌入式存储 + 无 LLM 纯检索路径，三者共同保延迟。

- **麒麟嵌入适配（lymem-kylin）**：`KylinEmbedder::connect_auto()` 双路探测——优先银河麒麟桌面 AI 运行时 DBus 通道（`/tmp/.kylin-ai-runtime-unix/<uid>/core-textembedding.sock`，随登录会话提供、可吃端侧加速），失败自动切换 kytensor HTTP 服务（`:8000`）；对外另暴露 OpenAI 兼容 `/v1/embeddings` 代理，供本机其他 Agent 复用同一嵌入。768 维，嵌入在端侧完成，数据不出机；
- **轻量化存储**：SQLite 单文件库 + sqlite-vec 向量 + tantivy 全文目录，无外部服务、无守护进程依赖；备份/迁移=拷贝目录；全量库（数千条级）端侧资源占用为 MB 级；
- **延迟保障**：检索路径纯本地三路召回+RRF（无网络往返）；LLM 仅在 `/ask` 生成与后台仲裁出现，且用 `spawn_blocking` 包裹不阻塞服务线程；
- **部署形态**（见 §6）：单二进制约 5MB，deb / 免 root 便携包即开即用，随桌面会话自启。

**实现落点**：`lymem-kylin/src/lib.rs`、`lymem-core/src/store.rs`、`embedding.rs`；界面底栏常显 嵌入后端/维度/LLM 状态。

**实测证据**：七站 442 查询逐题实测 **p50 27ms / p95 44ms / p99 55ms / max 100ms，超标 0/442**（目标 ≤500ms）；麒麟 V11 真机端侧嵌入下完成。

### 2.5 条款(5) 敏感信息识别与精准遗忘

> 集成敏感信息识别与过滤功能，支持自然语言指令驱动的精准遗忘操作，保障数据安全合规。

**设计**：入库前分级拦截 + 自然语言遗忘三段式（解析→预览→执行），全程可审计。

- **敏感识别（规则，零延迟）**：六类正则族——身份证/银行卡/手机号/密钥 Token/邮箱/IP；分级 `blocked`（密钥/证件类，**入库即拦截**）/`sensitive`（联系方式类，脱敏后入库）/提示；`redact` 输出脱敏文本。接入管道②步消费同一实现，"识别-过滤-入库"一体；
- **精准遗忘三段式**：
  1. `forget/parse`：自然语言指令 → 结构化范围 `scope{topics[],…}`。LLM 可用时语义解析（"忘掉关于部署路径的一切"→`topics:["部署路径"]`），无 LLM 关键词规则兜底；
  2. `forget/preview`：按 scope 圈定将遗忘的记忆清单（**先看后删**）；
  3. `forget/exec`：两档执行——**墓碑软删**（默认，可审计可恢复）与硬清除（物理删除）；支持整库遗忘；
- **审计闭环**：每次遗忘（含恢复）写 `audit_log`；界面提供"遗忘前/后同题检索对比"，效果肉眼可验。

**实现落点**：`lymem-core/src/sensitive.rs`、`forget.rs`；API `/api/v1/sensitive/scan`、`/forget/parse|preview|exec`；界面「遗忘与安全」页（四步向导+前后对比、敏感扫描台）。

**实测证据**：样例文本一次命中 手机号/API 密钥/IP 三项（level=blocked）并给出脱敏文本；遗忘链路实测 parse→preview（命中 3 条）→exec→同题检索 0 命中。

### 2.6 条款(6) 短期、中期记忆流转

> 兼容与记忆模块中短期、中期记忆间的数据流转。

**设计**：四层体系内建两条晋升边 + 一条消费边，流转全自动且可手动触发。

```
工作记忆(内存环形缓冲,render_context 注入当前会话)
   │ ①flush：会话结束/缓冲满 → 批量落库
   ▼
情景记忆(中期,轨迹原文)
   │ ②consolidate 蒸馏：按 scene+实体聚类分组，组内 ≥min_group 条且
   │   访问度 ≥min_access 才升级——"被反复用到的记忆才配长期化"
   │   LLM 可用→摘要式蒸馏(多轨并一条知识)；否则抽取式(按访问度/置信度选代表)
   ▼
知识记忆(长期) ──③消费边──▶ 检索重排 / 偏好快通道 / 中枢分发
```

- 晋升即走 2.3 冲突管道（蒸馏产物与既有知识碰撞仲裁），保证长期层始终自洽；
- 与外部短期/中期记忆兼容：会话轮次经 `conversation` 事件进入同一条管道，MCP 工具（DSH 集成）让外部 Agent 的会话上下文直接读写本记忆系统；
- `/api/v1/status` 实时给出四层计数，界面总览页管道图即本机制的直读视图，一键"蒸馏一轮"可手动触发。

**实现落点**：`lymem-core/src/promotion.rs`；API `/api/v1/consolidate`、`/status`；界面「总览」页流转管道图（各层计数+蒸馏按钮）。

**实测证据**：蒸馏链路实测通过（新增知识 N 条并出具 id）；总览 KPI 实时反映四层计数变化。

### 2.7 条款(7) 量化评测机制

> 设计量化评测机制，通过标准化数据集验证偏好提取准确率、知识检索召回率等核心指标，形成完整测试报告。

**设计**：三层评测集矩阵 + 公平对比协议 + 在线可复现评测。

- **评测集矩阵**（公开为主 + 自建补充，dev/test 分层防泄漏）：
  - 知识检索召回：MS MARCO / TrecQA / ToolBench / MultiWOZ / PersonaChat / DailyDialog / BPMN 七站公开集 + 自建中文长文档集"整本书问答·三国"（62 万字 120 回，51 题）；
  - 长程对话：LoCoMo 全量 1,986 问，免 LLM 严格协议（hit@5），杜绝判分器噪声；
  - 偏好与记忆能力：PrefEval / MemBench 必答 MCQ 协议（各 100 题）；
  - 冲突处理：受控冲突用例 30 组（numeric/method/premise/value_conflict 分型覆盖）；
- **公平对比协议**：基线 mem0、iwe 可本地运行，接入**同一麒麟嵌入与同一 MiniMax 生成网关**，同题同协议——比较的是记忆机制本身而非模型差异；
- **在线评测**：`/api/v1/arena/run` 对**当前活库**实时跑 hit@5 与延迟分位，内置两套样例数据集（隔离场景灌入不污染用户库）+ 自定义题目输入；界面「评测对比」页分组条形图直读结果，评测口径全公开。

**实现落点**：`benchmark/` 仓（数据、脚本、`results/REPORT.md` 完整报告）；服务端 `/api/v1/arena/run`；界面「评测对比」页。

**实测证据**：见 §4 指标表；对比结论——七站中文/公开集召回全面 ≥85%，偏好类大幅领先 mem0（98.0 vs 73.0 / 94.0 vs 55.0）。

### 2.8 超出条款的自选增强：经验复用层（借鉴 WikiSkill）

> 参考 WikiSkill（arXiv 2608.27454）：把 agent 执行经验编译进持久知识库（wiki），技能与知识共演化。

**设计**：在四层体系内（不新增记忆层）实现"轨迹 → 经验卡 → 技能演化"闭环：

- **经验卡** = 知识记忆（做法→workflow / 避坑→case）+ `meta.experience` 结构化字段（trigger 适用条件、steps 要点、outcome 复用成败计数、source_ids 证据链、status 状态）；
- **编译**（`experience.rs`，纯新增模块）：情景层轨迹按 场景+任务 分组、按成败分流，成功组提炼「做法」、失败组提炼「避坑」；LLM 提炼 trigger/steps，规则兜底（统计式，离线可用）；入库即走 2.3 冲突四步管道——**经验页随新旧碰撞自动合并/取代/共存**（合并幸存卡自动继承经验字段）；源轨迹打标防重编；
- **门控状态机**（WikiSkill 的 gating 思想）：`draft →（复用 ≥2 次且无失败）→ verified`，任何失败反馈回退 draft，永不物理删除（被拒经验也留知识）；
- **消费通道**：检索提权（verified ×1.25 / draft ×1.1，core 检索语义不变）；MCP 新工具 `experience_list` / `memory_feedback`（反馈顺带回写工具轨迹，形成下一轮编译原料闭环）；hub 分发经验前置注入（verified 优先）。

**对 agent 的价值验证**：DSH Agent 三臂对照 benchmark（同一 LLM 同一任务集，ToolBench 原生 train + 生成 test）——base（无记忆）/ +记忆检索 / +经验复用层，见 `benchmark/results/AGENT_EVAL.md`。
**MiniMax-M3 agent 实测：EM 90.0% → 96.7%（+6.7pts，零回退），而未编译的原始记忆检索为 -3.3pts**——"先编译、再注入"是记忆→能力转化的关键路径；强模型（gpt-5.6-sol）接近饱和（93-97%）。

### 2.9 性能微优化（AlloyStack 思路移植）

借鉴 AlloyStack（EuroSys 2025）的两个优化目标并移植到 lymem 形态（不引入其 LibOS 本体，适用性分析见 `docs/alloystack-notes.md`）：
"按需加载/冷启动" → LLM 探测后台化、启动即 bind；"引用传递/减少拷贝" → 检索热路径去冗余（候选批量拉取、RRF 融合 HashMap 化、
权重读一次、touch 单事务、PRAGMA 补齐、查询向量 LRU 缓存）。**442 题逐题召回与优化前完全一致，p50 16.5ms（-28%）、
p95 29.4ms（-27%），零超标**，详见 `benchmark/results/PERF.md`。

## 3 创新点设计（对应评审"技术创新性"）


1. **偏好双通道提取 + 证据链版本时间线**（2.2）：规则快通道保证离线可用与可解释置信度，LLM 慢通道覆盖软性陈述；每条偏好带 evidence 溯源到原始记忆 id，版本链支持任意时点回放——超越 mem0 等"当前值快照"式偏好存储；
2. **写入即冲突四步管道**（2.3）：检测（实体门+语义门双门槛）→分型→规则优先仲裁→版本化台账，冲突处理前移到写入时刻而非检索时发现，`decided_by` 全落账可审计；
3. **三路混合检索 + 偏好感知重排**（2.3）：向量/BM25/实体图三路 RRF 融合取长（语义泛化、词面精确、多跳关联），再按生效偏好提权——检索结果随用户习惯演化；
4. **多 Agent 记忆中枢**（hub，超出条款的自选创新）：自动发现本机各终端 Agent（ZCode/Claude Code/Codex/DSH…）的记忆/规则文件 → 一键导入汇聚 → 全库实体共现聚类（主题簇）→ 跨源矛盾扫描仲裁 → 按需**分发回**目标 Agent 规则文件（只写受管区块 `<!-- lymem:begin/end -->`，不动用户内容、可整体撤回）。把"单 Agent 记忆优化"升级为"整机记忆资产总管"。

## 5 真实场景应用案例

1. **编码 Agent 记忆接入（DeepSeek Harness 集成）**：`integrations/deepseek-harness/` 提供 `dsh web --patch lymem.cordis.yml`，DSH Agent 启动即获得 6 个 `mcp__lymem__*` 工具（写入/检索/偏好/遗忘…），跨会话记住项目部署路径、编码约定与个人习惯——多 Agent 中枢亦可将其记忆与本机其他 Agent 汇聚分发；
2. **整书记忆与问答（62 万字长文档压测）**：《三国演义》120 回 REST 分批灌入，KPI 144 记忆/126 章节块，书山 51 题召回 96.1%，检索 20–43ms——验证大规模沉淀下的存储与检索稳定性；
3. **办公自动化偏好沉淀**：连续工具调用（libreoffice/wps 文档编辑）→ 快通道自动沉淀 `tool_choice.doc_edit`，置信度=使用占比，后续检索自动提权常用工具——即赛题背景"工具选择偏好不精准"的直接解法演示。

## 6 工程与交付

- **源码可读性**：Rust workspace 模块化，每个核心模块头部文档注释给出"职责 + 管道图 + 对应条款"，关键算法（RRF、冲突门槛、蒸馏分组）参数显式可调；评测脚本与数据目录化，结果可复现；
- **麒麟适配**：嵌入走银河麒麟桌面 AI 运行时（DBus per-uid）+ kytensor 双路；实测于麒麟 V11 真机；服务以桌面登录用户运行（与嵌入通道同 UID），随会话自启；
- **即开即用封装**（`packaging/`，一键 `build-dist.sh`）：`lymem_0.1.0_amd64.deb`（root 安装：/opt/lymem + 菜单项 + 登录自启 + /etc/lymem/env）与免 root 便携包（`install-user.sh` 装入 ~/.local，含菜单/图标/自启/`lymem` 命令）；`lymem-ctl {start|stop|status|open|logs}` 统一控制；数据全在 `~/.local/share/lymem`，拷贝即迁移；
- **界面无门槛**：Web 管理台 7 页全中文，每项能力配可亲手操作的引导（示例数据、一键演示、前后对比），功能导览页给出能力→页面索引。
