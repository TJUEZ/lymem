# lymem 竞赛实施路线图

## 结论

现有项目的核心算法、端侧架构和演示功能已经超过一般原型。当前主要短板不是继续增加记忆概念，而是把能力做成“可复现、可操作、可证明”的产品闭环。优先级应按判零风险、评分权重和现场演示失败概率排序。

## P0：提交前必须完成

| 工作 | 完成标准 | 对应风险/得分 |
|---|---|---|
| 麒麟向量数据库 SDK 合规闭环 | 明确系统向量数据库 SDK 的真实调用代码、运行日志和真机截图；若当前仅使用 sqlite-vec，需补官方 SDK 主通道或取得赛方书面确认 | 赛题解读明确要求，存在判零风险 |
| 一键部署与验收 | 按 `docs/部署指南.md` 在干净 V11 用户环境复测；产物带校验和、版本和 commit | 可行性、文档规范性 |
| 指标可追溯 | 每项指标固定 dataset/version/split/command/commit/raw result；页面不再只写静态数字 | 性能 25 分、答辩可信度 |
| 真实 Agent 闭环 | 工具调用写入、偏好/知识形成、跨会话召回、影响下一次决策，全程 3 分钟内可演示 | 实用性、复评功能完整性 |
| 数据安全闭环 | 导出/备份、恢复、软删恢复、硬删除、审计导出；证明隐私数据不外发 | 条款 5、实际使用 |
| 提交物一致性检查 | README、PPT、报告、页面指标和版本号自动核对，清理绝对路径和密钥 | 文档 5 分、提交事故 |

## P1：管理台对标 mem0 的关键能力

1. **统一记忆表格**：服务端分页、类型/来源/场景/时间/敏感级别筛选、排序、批量选择。
2. **编辑与生命周期**：查看原文、编辑元数据、归档、软删恢复、硬删除、版本 diff。
3. **全局检索**：顶部搜索入口，统一检索记忆、偏好、知识、Agent 来源，支持保存筛选视图。
4. **导入导出**：JSON/JSONL/CSV 导出，导入预览、字段映射、失败行下载、重复策略选择。
5. **系统状态**：真实嵌入通道、模型、维度、DB 大小、索引状态、p50/p95、最近错误。
6. **可观察性**：每次检索展示向量/BM25/图通道分数、RRF 合并过程和最终引用。
7. **设置页**：数据目录、保留策略、敏感规则、LLM、端口和 Agent 集成状态集中管理。
8. **首次使用向导**：环境检测 -> SDK 检测 -> 演示数据 -> Agent 接入 -> 首次检索。

视觉层保持安静、紧凑和一致。当前具体问题包括：单文件 HTML 维护成本高、移动端导航缺少图标、动作按钮缺少图标与 loading 状态、危险操作确认不统一、表格缺少分页和批量动作、页面指标静态写死。建议先拆分 CSS/组件/页面模块，再做局部视觉升级。

## P1：核心能力增强

| 能力 | 建议实现 | 验证方式 |
|---|---|---|
| 记忆写入策略 | importance/novelty/usefulness 三分量门控，避免“所有内容都记住” | 写入精确率、压缩率、下游任务成功率 |
| 记忆更新 | ADD/UPDATE/MERGE/DELETE/NOOP 显式决策，保留理由与证据 | 冲突集 + 人工标注混淆矩阵 |
| 时间语义 | valid-time 与 transaction-time 双时间，支持事实过期和“当时正确” | 时间问答、历史回溯准确率 |
| 检索自适应 | 按查询类型选择向量/BM25/图/时间过滤权重，而非固定融合 | LoCoMo/中文库消融实验 |
| 记忆压缩 | 同主题聚类摘要，同时保留原始证据链和可逆引用 | token 节省率与答案保持率 |
| 使用反馈 | 记录被召回、被采用、任务成功/失败，驱动衰减和晋升 | 在线命中后的任务成功率 |
| 多租户边界 | user/agent/workspace 三层 namespace 和权限隔离 | 越权检索负例测试 |

## P2：答辩加分项

- **记忆可解释性视图**：展示“为什么记、为什么召回、为什么更新、为什么遗忘”。
- **资源预算仪表**：CPU、内存、磁盘、嵌入吞吐、冷启动，和 mem0 等基线同机对比。
- **场景化模板**：办公自动化、系统运维、个人文件助理三个预设策略。
- **故障注入演示**：主动关闭 DBus 或驱逐模型，展示无中断降级与恢复。
- **ARM64 真机适配**：飞腾/鲲鹏平台发布包与报告。

## 建议迭代顺序

1. 合规审计：确认官方向量数据库 SDK 是否已真实使用。
2. 固化部署、验收、评测和提交构建，保证任何人能复现。
3. 完成统一记忆表格、批量操作、导入导出、备份恢复和设置页。
4. 做一个真实 OS Agent 跨会话闭环，并以此反推界面和 API 缺口。
5. 最后再做视觉抛光、动效和答辩加分项。

## Git 管理约定

- 每个可验证能力一个小提交，例如 `docs: add Kylin V11 deployment runbook`。
- 评测结果记录代码 commit、数据集 hash 和完整命令，原始结果不可覆盖。
- 发布版本使用 tag，构建产物写入版本、commit 和 SHA-256 校验和。
- 功能提交与大体积评测产物分开，避免无法审查的混合提交。
- 提交前运行格式化、测试、文档链接检查和敏感信息扫描。
