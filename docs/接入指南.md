# lymem 接入指南

把 lymem 接到你桌面上的任意 Agent，三种方式按接入深度排列：

| 方式 | 做什么 | 适合谁 |
|---|---|---|
| ① hub 文件汇聚 | lymem 自动发现并汇入 agent 已有的记忆文件，再把记忆/偏好回写进它们的规则文件 | 已在用 zcode / claude-code / codex / gemini 的用户（零代码） |
| ② REST 直连 | agent 程序直接调记忆 API | 自研 agent 的开发者 |
| ③ 嵌入代理 | 只把 lymem 当系统嵌入服务用 | 只要合规嵌入、不需要记忆管理的场景 |

前置：服务已启动（`LYMEM_PORT=8801 ./target/release/lymem-server`），
`curl http://127.0.0.1:8801/api/v1/health` 返回 ok。

---

## 方式 ①：hub 文件汇聚（推荐，零代码）

lymem 能发现本机终端 agent 的记忆载体（zcode / claude-code / codex（含记忆
SQLite）/ gemini / opencode / 通用 AGENTS.md、CLAUDE.md），两条命令完成"汇入 +
回写"：

```bash
# 看看发现了哪些源
curl http://127.0.0.1:8801/api/v1/hub/sources

# 汇入发现的记忆（幂等，重复执行不产生重复记忆）
curl -X POST http://127.0.0.1:8801/api/v1/hub/import

# 把 lymem 的记忆/偏好/实体摘要回写到各 agent 的记忆/规则文件
curl -X POST http://127.0.0.1:8801/api/v1/hub/dispatch
```

回写只落在 `<!-- lymem:begin/end -->` 受管标记块里，agent 自己写的内容一律
不动；敏感信息自动脱敏后才回写。自定义源用 `LYMEM_HUB_EXTRA` 注册。

界面党：viewer →「Agent 中枢」页，源发现 / 汇入 / 调度 / 总索引 / 巡检全部
可视操作，等价于上面三条命令。

## 方式 ②：REST 直连（自研 agent）

最小接入三步：

```text
1. 任务开始：  POST /api/v1/search  {"query":"<任务>","top_k":8}
              → 返回相关记忆，作为上下文注入提示词
2. 过程产出：  POST /api/v1/memories {"events":[...]}
              → 工具结果 / 用户偏好 / 事实变更随时写入
3. 会话结束：  POST /api/v1/consolidate
              → 情景记忆评分晋升，蒸馏出经验卡
```

事件格式与完整字段见根目录 `AGENTS.md`（那份是写给 agent 的操作规范，
人读它也一样能看懂协议）。偏好、冲突、遗忘接口见下表。

## 方式 ③：嵌入代理

OS Agent 主程序把 embedding 基址从云端换成 `http://127.0.0.1:8801/v1`，
模型名随便填（服务端固定转发到麒麟 gte）。文本不出本机。

## API 速查

| 操作 | 接口 |
|---|---|
| 写入事件 | `POST /api/v1/memories` `{"events":[...]}` |
| 检索 | `POST /api/v1/search` `{"query":"…","top_k":8,"scenes":["office"]}`；脚本也可用 `GET /api/v1/search?query=…&top_k=8` |
| 偏好列表 / 时点回溯 | `GET /api/v1/preferences` / `GET /api/v1/preferences/at?at=<ISO>` |
| 冲突列表 / 仲裁 | `GET /api/v1/conflicts` / `POST /api/v1/conflicts/{id}/resolve` |
| 遗忘预览 / 执行 | `POST /api/v1/forget/preview` / `POST /api/v1/forget/exec` |
| 蒸馏晋升 | `POST /api/v1/consolidate` |
| 审计 | `GET /api/v1/audit?limit=50` |
| hub 三件套 | `GET /hub/sources` · `POST /hub/import` · `POST /hub/dispatch` |

## 技能文件接入（推荐用于跨模型迁移）

在管理台进入「知识与冲突 → 技能发布」，选择 Codex、Claude Code、OpenCode 或
DeepSeek Harness，点击「发布技能」。系统把经验卡与当前偏好编译为：

```text
<agent skills dir>/lymem-experience/
  SKILL.md
  resources/manifest.json
  .lymem-versions/        # 上一版快照，供回滚
```

`SKILL.md` 包含适用条件、可执行步骤、避坑规则、复用统计和来源证据。发布新版本前
自动保留旧版；界面可一键回滚或移除。Agent 下次会话会按自身技能发现机制加载它。
MCP 负责实时读写，技能文件负责低成本常驻过程知识，两者互补。MCP 还提供
`experience_compile`、`skill_targets`、`skill_publish`，Agent 可以自己完成经验到技能的编译发布。
何时写记忆、如何检索、遗忘协议、偏好使用规则。手动接入的 agent，把该文件
内容复制进它的系统提示或规则文件即可。

## 排障

| 现象 | 处理 |
|---|---|
| health 不通 | `lymem status` 逐项自检；向量引擎 socket 缺失用 `engine-supervisor.sh` 拉起 |
| hub/sources 为空 | 确认对应 agent 装过且跑过至少一次；自定义路径用 `LYMEM_HUB_EXTRA` |
| 检索结果不相关 | viewer 图谱页确认记忆已入库；给查询带 `scenes` 限定场景 |
| 嵌入报错 | `LYMEM_EMBEDDER=hash` 临时降级，再查麒麟 SDK 通道 |
