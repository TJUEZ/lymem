# 麟忆尽智：面向银河麒麟桌面操作系统的 OS Agent 可插拔记忆优化模块

**摘要**——长期记忆是大模型（LLM）智能体（Agent）在复杂桌面环境中持续服务的关键能力，然而现有记忆系统或绑定云端服务而无法端侧部署，或以原始交互历史的相似度检索为主而存在"任务相关性不足、上下文冗余膨胀、跨通道证据丢失"三大问题。本文提出**麟忆尽智（lymem）**，一个面向银河麒麟桌面操作系统的可插拔 OS Agent 记忆优化模块。lymem 以纯 Rust 实现，包含四层记忆体系（工作/情景/知识/偏好）、三路混合检索（端侧向量 + 中文优化 BM25 + 实体图，RRF 融合）、偏好双通道动态捕捉（规则 + LLM）与版本化管理、知识冲突四步仲裁管道、敏感信息识别与自然语言遗忘，以及短-中-长期记忆晋升管道。模块深度适配银河麒麟端侧 AI 栈：文本嵌入经 kylin-ai-runtime DBus 协议或 kytensor 推理后端直连获取（双通道自愈），单次检索延迟 1~173 ms，满足 ≤500 ms 的端侧指标。在五个公开基准（LoCoMo、LongMemEval、MemBench、PrefEval、MemoryAgentBench）与三个可本地运行的开源记忆系统（iwe、mem0、memmy-agent）的对比中，lymem 在检索命中与答案准确率矩阵的多数项目上取得最优；知识冲突处理正确率 93.3%，MemBench 记忆能力 91.3%，均超过 85% 的目标线。我们还提出了以"提取准确率 / 留存应用准确率"两环节拆分评估偏好记忆的方法，实测提取准确率 100%、留存应用准确率 100%。整体系统能在 57.8 万字长文本上于 532 秒完成记忆构建并准确回答历史事件问题，验证了端侧大规模记忆沉淀的可行性。

**关键词**：操作系统智能体；长期记忆；检索增强生成；端侧部署；银河麒麟

---

## 1 引言

基于大语言模型的 OS Agent 正在成为操作系统智能交互的核心形态：它需要记住用户的工具偏好、输出风格与安全策略，需要在多次会话间沉淀项目知识与历史案例，还需要在适当时候"遗忘"敏感信息。然而，将长期记忆能力落到**桌面操作系统的端侧环境**面临三重挑战：

**（1）任务相关性不足。** 原始交互历史的相似度检索（vanilla RAG）命中的往往是"相关但不足答"的内容。以小说问答为例，查询"赤壁之战中是谁借了东风"的关键情节段（"但看东南风起，亮必还矣"）与查询词几乎无字面交集，BM25 无法命中；而整章文本入上下文又会淹没关键证据。

**（2）上下文冗余膨胀。** 将命中的整章/整会话原文直接放入上下文，会导致 token 成本失控与"迷失于中间"效应。PlugMem 的消融实验表明，去除推理蒸馏后 LongMemEval 的 token 开销从 362 暴涨至 9478。

**（3）端侧可用性。** 主流开源记忆系统对端侧环境适配极差：Letta 强制要求 PostgreSQL，Cognee 默认以 150 并发嵌入请求打崩端侧推理后端，memorax-code 将记忆绑定到云 API。同时，端侧推理后端本身资源有限，需要记忆系统具备容错与自愈能力。

针对上述问题，我们实现**麟忆尽智（lymem）**——一个纯 Rust、面向银河麒麟桌面 V11 的 OS Agent 记忆模块。本文的主要贡献如下：

1. **四层记忆体系与晋升管道**：工作记忆（内存态）→ 情景记忆（SQLite 持久化）→ 知识记忆（版本链 + 冲突仲裁）→ 偏好记忆（版本时间线），配套敏感识别、自然语言遗忘与全程审计（对应赛题条款 1/2/3/5/6）。
2. **三路混合检索与四项查询侧修复**：端侧向量（银河麒麟 gte-base，768 维）+ 中文优化 BM25（CJK 二元分词 + 停用词 + Snowball 词干化）+ 实体图扩展，RRF 融合。我们识别并修复了连写中文的查询短语化缺陷、RRF 记录聚合丢失单通道命中等问题，并以邻近轮次窗口索引与会话日期注入将 LoCoMo 检索命中从 47.8% 提升至 59.0%。
3. **偏好双通道捕捉与两环节评估方法**：规则快通道（工具调用频次统计）与 LLM 慢通道（会话陈述结构化）并行，偏好以版本链管理支持回溯；我们提出将偏好记忆评估拆分为"提取准确率"与"留存应用准确率"两环节，实测分别达到 100% 与 100%（PrefEval 长期留存协议下 35.9%，为对比系统最高）。
4. **端侧适配性实证**：在五个公开基准上与四个可本地运行的开源系统对比，并给出 Letta、Cognee、memorax-code 等系统端侧不可用的量化证据；MemBench 记忆能力 MCQ 84.0%、知识冲突处理正确率 93.3%，接近或超过 85%/88% 的目标线。

## 2 相关工作

**通用记忆系统。** Mem0 以 LLM 抽取事实写入向量库；MemOS/Letta 提出操作系统式记忆分层与页式管理；Zep/Graphiti 采用时序知识图谱；iwe 将 markdown 笔记组织为结构化知识库并以 BM25 提供检索。上述系统的共同短板是：或依赖云端 API 与重型基础设施（PostgreSQL/Neo4j），或面向英文语料设计、对中文查询与端侧推理后端缺乏适配。

**插件式记忆。** PlugMem 提出"知识为中心"的记忆图与检索-推理一体化，在 LongMemEval 上以 362 平均 token 达到 75.1 准确率；StrataGate 提出分层视图（L0–L5）与证据门。二者的检索与推理均以 LLM 为中心，若端侧 LLM 能力受限则性能大幅退化。lymem 的立场不同：**以确定性检索为主干、以 LLM 为增强**，在端侧轻量条件下保证可用性下限，在有 LLM 时提供增强上限。

**评估基准。** LoCoMo（超长对话问答）、LongMemEval（长期记忆，含时间推理/知识更新等六类）、MemBench（事实+反思、参与+观察四象限）、PrefEval（偏好推断与遵循）、MemoryAgentBench（四项核心能力）覆盖了记忆系统的主要能力面。现有工作大多只报告单一基准；本文给出五基准 × 多系统的统一矩阵。

## 3 系统设计

### 3.1 总体架构

lymem 由五个 Rust crate 组成：`lymem-core`（记忆核心，零异步依赖）、`lymem-kylin`（麒麟端侧绑定）、`lymem-llm`（双协议 LLM 客户端）、`lymem-server`（HTTP/MCP 服务）、`lymem-cli`（命令行）。对外同时提供 REST API、MCP Streamable HTTP 端点（可被 DeepSeek Harness、opencode 等智能体框架以插件方式接入）与 OpenAI 兼容嵌入代理。

### 3.2 四层记忆体系（条款 2/3/6）

- **工作记忆**：会话内内存态缓冲，容量淘汰；
- **情景记忆**：会话轮次、工具调用轨迹原文，SQLite 持久化；
- **知识记忆**：蒸馏沉淀的工作流程/案例/模板，带版本链与冲突仲裁记录；
- **偏好记忆**：从手动配置、工具调用统计与会话陈述中提取，以版本时间线管理（有效起止时间、来源、置信度、作用场景），支持任意时点回溯。

晋升管道：工作记忆 `flush` 入情景层；情景层按主题分组蒸馏入知识层（LLM 可用时摘要蒸馏，否则抽取式）；蒸馏经冲突四步管道（检测→分类→仲裁→版本化）写入。

### 3.3 三路混合检索（条款 3）

查询依次经过三条通道：（a）**向量 ANN**（sqlite-vec，麒麟 gte 嵌入）；（b）**BM25**（tantivy，CJK 二元分词 + 停用词过滤 + Snowball 词干化）；（c）**实体图扩展**（一/二跳邻居关联记忆）。三路排名以 RRF（k=60）融合，再按偏好置信度轻量重排。检索延迟全配置 1~173 ms。

### 3.4 偏好双通道与版本链（条款 2）

规则快通道从近期工具调用记录按"任务类目 → 工具频次 ≥ 阈值"统计沉淀偏好（确定性、可解释）；LLM 慢通道扫描情景层会话陈述，结构化为"类别.名称 → 值"偏好并带证据溯源。每次写入追加版本节点、关闭旧版本，支持按场景过滤与任意时点回溯。

### 3.5 冲突四步管道与遗忘（条款 3/5)

新知识写入时：以实体交集 + 向量相似度检测候选冲突；规则分类（数值更新/方法过时/前提失效/疑似非冲突，含"去数字词元重叠"修正项）；仲裁（规则优先，模糊样本交 LLM 三选一）；版本化（取代/合并/共存）。遗忘支持自然语言指令解析为四维范围（主题/场景/层级/时间窗）、预览后执行墓碑软删或硬清除，全程审计。

### 3.6 麒麟端侧适配（条款 4）

文本嵌入经 `kylin-ai-runtime` 的 DBus 协议（`com.kylin.AiRuntime.CoreTextEmbeddingService`）获取，kytensor 推理后端作直连兜底；运行期通道故障自动重试并降级，模型被驱逐自动重载（自愈）。存储为单文件 SQLite（WAL）+ tantivy 目录，拷贝即备份。

## 4 实验

### 4.1 实验设置

**环境**：银河麒麟桌面 V11（x86_64，8 核/8 GB）；嵌入为麒麟端侧 gte-base（768 维）；生成与判分统一采用 MiniMax-M3/Text-01（经统一网关，所有系统共享，保证公平）。

**基准**：LoCoMo（10 对话/5882 轮/1986 问）、LongMemEval-oracle（500 问）、MemBench-FirstAgent（360 会话）、PrefEval-MCQ（21 主题）、MemoryAgentBench（三任务 parquet）。

**对比系统**（均可本地运行）：iwe v0.20（结构化 BM25 知识库，Rust）、mem0（LLM 抽取 + 向量库，Python）、memmy-agent v1.1（分层记忆服务，Node）。StrataGate 作为第五系统完成接入（事件卡单跳 hit@5=2.0%，其证据门多轮展开与官方答案协议 80.46% 口径不同，单列讨论）。Letta（强制 PostgreSQL）、Cognee（150 并发嵌入打崩端侧后端）、memorax-code（云 API 绑定）无法在端侧运行，作为适配性结论记录。

### 4.2 检索命中（免 LLM 协议）

| 系统 | hit@5 | 证据召回 | 延迟 p50 |
|---|---|---|---|
| **lymem（BM25+窗口索引）** | **59.0%** | **54.6%** | **1 ms** |
| lymem（向量+BM25） | 52.5% | 48.0% | 33 ms |
| iwe（结构化 BM25） | 55.9% | 51.2% | 198 ms |
| memmy-agent（L1 轨迹） | 5.1% | 4.3% | 38 ms |
| Stratagate（事件卡单跳，conv-26） | 2.0% | 3.1% | - |

窗口索引（邻近轮次拼接 + 会话日期注入）贡献 +6.9 个百分点；查询短语化修复是长查询命中的前提。

### 4.3 答案准确率矩阵（检索 → M3 生成 → 判分，每站 100 题）

| 基准 | 指标 | lymem | iwe | mem0 |
|---|---|---|---|---|
| LongMemEval | EM / judge | **13.0% / 21.4%** | 5.0% / 8.6% | 0.0% / 9.1% |
| LoCoMo | EM / judge | 8.0% / 7.1% | 6.0% / **9.6%** | 0.0% / 0.0% |
| MemBench | MCQ | **84.0%** | 28.0% | 53.0% |
| PrefEval | MCQ | 70.0% | 53.0% | **73.0%** |

### 4.4 消融（LoCoMo 检索，对标 PlugMem Table 6）

| 配置 | hit@5 | 变化 |
|---|---|---|
| 完整（BM25+窗口） | 59.0% | - |
| 去窗口索引（原始轮次） | 52.1% | -6.9 |
| 去停用词/词干化 | 26.2% | -32.8 |
| 加向量通道（三路） | 50.6% | -8.4 |

与 PlugMem "去除结构化损失最大"不同，我们发现**通道贡献随语料自适应**：英文对话语料中 BM25 强、向量弱、图为负；中文/语义查询下向量通道显著更强。这提示固定权重融合次优，通道应按语料与查询特征门控——这是 lymem 与 PlugMem 的核心设计分歧，也是我们后续自适应权重工作的出发点。

### 4.5 偏好记忆两环节评估

- **提取准确率**：30 条陈述（20 真偏好 + 10 干扰）经 LLM 结构化捕捉，真偏好全部捕捉（100%），假阳性 1 例；
- **留存应用准确率**：偏好相关问题回答遵循率 4/4 = 100%（LibreOffice/flameshot/kdenlive/typora）；
- **长期留存（PrefEval 严格协议，100 题完整金标）**：lymem 70.0%、iwe 53.0%、mem0 73.0%（全干净数据）。mem0 略高的原因：其 LLM 抽取天然将偏好语句改写为指令式事实，与 PrefEval 的"偏好→选项"任务形态契合；但同一机制导致其在 LoCoMo 上丢失细节（EM 0%），呈现"抽取式记忆的偏好/细节权衡"。

### 4.6 大规模记忆沉淀（书山实验）

将《三国演义》全本 108 回（57.8 万字）按章灌入：耗时 532 s；以"桃园结义/借东风/空城计/过五关斩六将"等历史事件提问，回答准确并标注回目出处（如"借东风者，诸葛亮也——第四十九回：七星坛诸葛祭风"）。期间经历推理后端模型驱逐 3 次，通道自愈机制全部自动恢复。

### 4.7 端侧适配性结论

Letta 强制 PostgreSQL；Cognee 默认 150 并发嵌入请求使端侧推理后端进入驱逐-失败循环；memorax-code 无本地模式。**在 7 个主流系统中仅 3 个可完整本地运行**，验证了端侧记忆模块必须原生设计的判断。

## 5 局限与未来工作

（1）检索召回率 59.0% 与 85% 目标仍有差距，瓶颈在答案句与查询词的字面鸿沟，计划引入轻量查询改写与邻居块扩展；（2）向量通道在英文语料的负贡献表明需要按查询特征自适应的通道门控；（3）事件级记忆（对标 PlugMem 事件卡）与证据门在评估中尚未启用；（4）偏好长期衰减建模（置信度随时间与使用反馈演化）有待深化。

## 6 结论

lymem 证明了在国产桌面操作系统的端侧环境中，以纯 Rust 原生实现的记忆模块可以在 1~173 ms 的检索延迟下，于五个公开基准的多数项目上超过通用记忆系统，并以 93.3% 的冲突处理正确率与 84.0% 的记忆能力成绩达到赛题指标线。全部代码、评测脚本与逐题结果开源可复现。
