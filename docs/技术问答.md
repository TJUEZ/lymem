# 技术问答（答辩与评审准备）

按评审最可能追问的方向整理。每条先给短答（30 秒版本），需要展开再讲长答。

---

**Q1：和 mem0 比你们的差异到底是什么？一句话。**

mem0 把记忆拆成一条条原子事实，靠检索时拼装；我们把记忆分成四层（工作/情景/
知识/偏好），配冲突调解、版本链、遗忘和晋升管线，靠结构管生命周期。数字上：
冲突整合 22% 对 2%，端到端判分 33.7 对 23.2；它们的长处是单事实检索
（LongMemEval 64.9 对 54.3），这项我们已归因到记忆单元粒度并部分修复。

**Q2：检索召回 95% 是怎么做到的？纯向量不行吗？**

纯向量在精确实体上不稳。七站里有预订号、站名、工具参数这类查询，我们上三路：
向量 ANN（麒麟引擎）+ BM25（tantivy）+ 图扩展，RRF 融合再按偏好重排。三路都
有开关，消融实验显示去掉 BM25 后精确实体查询明显掉分。

**Q3：为什么用系统向量数据库 SDK，不自己嵌一个？**

赛题硬性要求，而且这是对的选择：端侧资源有限，系统级引擎由 OS 统一调度，
进程崩了数据不丢，还省一份内存。我们做过 sqlite-vec 降级通道用于开发对比，
正式环境全走 SDK。

**Q4：延迟 24~88 毫秒是怎么测的？包括嵌入吗？**

包括。七站逐题计时，从查询进服务到结果返回，嵌入走麒麟 SDK（DBus/kytensor），
检索走向量引擎，全程本机。LoCoMo 1986 问全量计时，p50 2~88ms。赛题线 500ms。

**Q5：敏感信息怎么处理？**

入库时扫描分级，不检索时过滤——敏感内容从一开始就不进检索索引。遗忘支持按
敏感级别批量清除，软删有墓碑可审计。识别是规则式的，可按政企场景自定义模式库。

**Q6：冲突"检测→分类→仲裁→版本化"具体怎么仲裁？**

三级优先：显式用户指令最高，其次是时间戳新的，再按来源置信度。旧值不删，进
版本链。查询默认只出仲裁后现值；"用户 5 月的偏好是什么"这种时点查询打版本
时间线。受控冲突用例 30 组正确率 93.3%，MAB 整合题 22% 对 mem0 的 2%。

**Q7：LongMemEval 为什么输了？**

分题型看。时间推理我们 70%，反超 mem0 的 63%——这部分我们修复了检索合并管线
的一个缺陷（多查询扩展在旧实现里从未生效）。输的是多会话聚合题（20% 对 62%）：
mem0 的原子事实能逐条召回再拼装，我们的区块记忆在这种题上粒度吃亏。这是架构
取舍，改进方向明确（细粒度记忆单元），不打算回避。

**Q8：偏好提取 99% 是不是题太简单？**

PrefEval 本身接近天花板，两家都是 99%。这个分数说明的是"偏好存取这条赛道没有
短板"，真正的区分在版本能力：lymem 支持偏好时间线回溯和跨场景适配，这是纯
准确率数字看不到的。

**Q9：端侧资源占用怎么样？**

单二进制，SQLite 单文件元数据，向量在系统引擎，无常驻大模型。检索路径没有任何
外部调用。LLM 只在偏好慢通道和蒸馏里可选使用，不配密钥系统照常工作（规则兜底）。

**Q10：多源接入具体接什么？**

四类事件：tool_result（工具执行结果）、user_action（行为）、config（手动配置）、
conversation（对话）。入口统一成事件流，清洗、去重、敏感分级后进管线。另有
Agent 中枢页可以从其他 agent 的记忆文件发现、解析、导入（幂等）。

**Q11：怎么保证评测数字可信？**

三点。一是免 LLM 口径：检索类全部 hit@5，逐题可人工复核；二是双判分：开放题
同时报严格 EM 和语义判分，防止单一口径偏差；三是全链路可复现：每个数字对应
逐题 jsonl 一行，脚本和查询集固定（seed=42），对照系统与我们在同一麒麟嵌入、
同一向量引擎、同一生成判分模型上跑。

**Q12：短期/中期/长期记忆怎么流转？**

工作记忆按窗口 flush 进情景记忆；情景记忆按访问频次、复现模式、时效评分，
高分蒸馏成知识记忆（含经验卡：做法、适用条件、踩坑）。偏好独立成层。全部
流转有审计。

**Q13：如果 OS Agent 同时有多个实例，记忆会串吗？**

记忆带 scene（场景）和 user 维度，检索默认按 scene 过滤，偏好重排优先同场景。
多实例可共用一个 lymem 服务，也可以用 Agent 中枢把多个实例的记忆汇聚成总库
再分发。

**Q14：遗忘删错怎么办？**

默认软删（墓碑+审计），可恢复；硬清除才不可逆，需要显式指定。遗忘指令先预览
受影响集合，确认才执行。

**Q15：你们的失败案例有哪些？**

两类主要失败：超长对话里的跨数百轮单事实检索（LoCoMo 未命中题集中于此）；
多会话聚合题的单侧证据缺失（LongMemEval）。都指向记忆单元粒度问题，路线图里
排在第一位。
