# 麟忆尽智 lymem · 评测总报告 v2（2026-08-30 统一定稿）

评测环境：银河麒麟 V11 端侧；嵌入统一为麒麟 gte-base（768 维，DBus/kytensor 自愈双通道，经 lymem-server
OpenAI 兼容代理统一供给全系统）；答案生成与判分统一 MiniMax-M3（经同一网关）；检索协议免 LLM、答案协议含
M3 生成+judge。本版合并并取代此前的两份矛盾报告（docs/REPORT.md 与本文件旧版），所有口径以下文为准。

## 〇、本版评测质量修正（相对旧版报告的关键增量）

旧版报告存在**对比系统结果不实/缺失与口径矛盾**，本轮逐项修复并重跑：

| # | 问题 | 根因 | 修复与结果 |
|---|---|---|---|
| 1 | mem0 的 LoCoMo 答案 0%/0% 明显不合理 | 灌入链路三层静默失败：kytensor 过载瞬态故障 + **超长文本嵌入 500**（gte 512-token 窗口装不下整段对话）+ LLM 抽取被 max_tokens 截断；add 失败被 mem0 静默吞掉，qdrant 实为空库（32KB） | lymem 嵌入代理增加**超长输入分块+平均池化**；mem0 配置 max_tokens=16384；增加**灌入校验门**（缓存 <1MB 判失败）。修复后真实成绩 **EM 16.0% / judge 14.1%**——旧版"mem0 LoCoMo 0%"结论作废 |
| 2 | 两份报告 MemBench 84% vs 91.3% 矛盾 | 91.3% 来自 r3 残缺重跑（分母 92/47/59 题，各系统题集不同不可比） | 定稿采用 r2 完整 100 题：lymem 84.0 / mem0 53.0 / iwe 28.0；r3 数据弃用归档 |
| 3 | memmy 缺失于全部答案矩阵 | mem0 本地嵌入模型（Xenova）需联网下载且 fetch 失败，向量检索长期不可用 | memmy 嵌入切换至 lymem 代理（openai_compatible，同一 gte 嵌入器，公平协议），重灌 5882 轮后补齐 LoCoMo 答案列 |
| 4 | lymem 的 LoCoMo 答案协议与其检索协议配置不一致 | 答案矩阵用裸轮次接入，未用其最优的窗口双视图索引 | r4 起答案协议对齐检索协议（双视图+检索后视图去重防止重复占用上下文槽位） |
| 5 | 文档写了 5 个 benchmark 但 MAB 从未跑过 | 无加载器 | 新增 MAB-conflict 加载与三系统矩阵（见第四节） |
| 6 | PrefEval 数字 35.9% 与 70% 并存且口径不明 | 两套协议：存储协议（偏好原文入库，四系统可比）与留存协议（偏好须挖掘，lymem 消融） | 矩阵采用存储协议；留存协议作为 lymem 单独消融保留并标注 |

## 二、LoCoMo 答案协议（每系统 100 题，EM=严格匹配 / judge=M3 语义判分）

| 系统 | 旧版（r3 或事故值） | 本版定稿 | 说明 |
|---|---|---|---|
| lymem（窗口双视图+视图去重） | 8.0 / 7.1（裸轮次接入） | **2.0 / 11.0**（对照：不去重 5.0 / 12.5） | judge 提升 +3.9pt；EM 波动属 n=100 噪声（±2 题） |
| iwe | 6.0 / 9.6 | 6.0 / 9.6（未变，配置未动） | — |
| mem0 | 0.0 / 0.0（空库事故） | **16.0 / 14.1** | 修复后真实成绩，EM 全场最高 |
| memmy（嵌入修复版） | 缺失 | 6.0 / 4.8 | 补齐 |

结论修正：旧版"mem0 LoCoMo 0%、抽取改写在本基准完全失效"的说法不成立——修复后 mem0 EM 16% 为四系统最高；
其 judge 14.1% 与 lymem 11.0%、iwe 9.6% 同一量级。LoCoMo 答案绝对值低是**全系统现象**（judge 均低于证据
召回率 30-50pt），主因是 M3 判分口径严格（数字/日期/人名必须一致）+ top-5 上下文窗口对多跳证据链覆盖有限。

## 七、关键发现（答辩要点，v2 增补）

1. **横向对比的最大误差源是基线系统的静默失败**：mem0 三层失败（嵌入 500/LLM 截断/空库静默）曾产出 0% 假象，
   修复后上修至 EM 16%。基线评测必须内置灌入校验门（体积阈值+失败计数），否则结论不可信。
2. **端侧嵌入代理的鲁棒性是接入公平性前提**：gte 512-token 窗口下，超长输入分块+平均池化让任意第三方系统
   （mem0/memmy）可直连同一麒麟嵌入器——这是"统一嵌入公平协议"能成立的基础设施。
3. lymem 在检索协议（hit@5 59.0%）与新增的 MAB-conflict（EM 18.0% 唯一非零）上保持领先；LoCoMo 答案协议上
   mem0 修复后 EM 反超——抽取改写在"精确值问答"上有真实优势，但以丢失证据细节为代价（其证据召回最弱）。
4. 通道贡献随语料自适应：英文对话 BM25 强、中文/语义查询向量强——固定权重融合次优，图通道在对话语料为负
   贡献需门控（消融数据见 results/ 目录各 r 轮 JSON）。
5. 大规模记忆沉淀：《三国演义》108 回/57.8 万字 532s 灌入，历史事件问答准确并引用回目。
